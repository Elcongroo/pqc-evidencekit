# MVP 的结构与扩展边界

这个项目把可用的上游 TLS 工具组织成一个可复现实验入口。Python 负责目标校验、探测计划、进程边界、解释与报告；密码算法与 TLS 状态机由用户指定的 OpenSSL 执行。

```mermaid
flowchart LR
    U[用户：目标 / SNI / 信任 / 混合组] --> D[doctor：本地能力]
    D --> P[多组新握手计划]
    P --> O[OpenSSL s_client]
    O --> R[原始输出]
    R --> C[分别解释组、身份、签名、错误]
    C --> J[JSON 与离线 HTML]
    R --> H[SHA-256 清单]
    J --> H
```

## 需求到结果的对应

| 需求 | 控制项 | 真实执行路径 | 结果与边界 |
| --- | --- | --- | --- |
| 判断对应混合交换能力 | `--groups` 与限定组提案 | 本机 `openssl s_client -tls1_3 -groups ...` | 完成握手与实际组；不直接观察远端秘密 |
| 归因到预期服务 | `--servername`、`--cafile` | SNI、服务名称与信任验证 | 身份验证结果；不等于 PQ 认证 |
| 解释传统路径 | `X25519` 对照与混合提案 | 每种条件使用新进程、新连接 | 允许/选择行为；不等于攻击诊断 |
| 可复查 | `--out`、原始日志与哈希 | 保存进程输出再生成派生结果 | 可追溯本次观测；不等于可信见证 |
| 无外部环境也能复现 | `demo` | 临时证书与回环地址上的两台演示服务 | 真 TLS 对照；不等于设备验收 |

报告必须记录实际调用参数与可用版本。目标输入不拼进 shell 命令字符串。超时、解析失败、验证失败等应保留原始理由，避免用一个布尔值掩盖不确定性。

## 未来 IKEv2/IPsec 扩展

当前没有 IKE 探测实现。它不能简单套用 TLS 的命名组输出：通常需要有权限的双端测试配置，处理 IKE 提案、多个交换、认证、IKE SA、CHILD SA 和业务流量。仅远程响应 IKE_SA_INIT，不足以证明附加 PQ 交换或最终隧道已经成功。

合理的下一步是先增加一个受控 strongSwan 双端适配器，按[附加交换 RFC 9370](https://www.rfc-editor.org/rfc/rfc9370.html)与[IKE_INTERMEDIATE RFC 9242](https://www.rfc-editor.org/rfc/rfc9242.html)定义独立判据，再保存双方配置、运行身份、日志、原始 PCAP、SA 和数据面结果。实现完成前不在 CLI 或 README 中宣称支持。

## 先保持易用，再扩大范围

- 首次使用先有 `doctor`，让客户端环境问题得到明确说明。
- `demo` 为正向/反向对照提供一个稳定入口。
- HTML 面向人工阅读，JSON 与退出码供回归流程使用。
- 扩展应增加独立观察维度；不要把“抗量子能力”合成没有边界的总分。
- 运行数据默认不进入 Git；公开示例使用本地临时环境。
